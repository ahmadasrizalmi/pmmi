# G5 — Ops: ops-monitor + backup/restore drill

Tanggal: 2026-08-22. Server: `pmmiserver`. Disk: root 100G (`/`, sda3), HDD 465.8G (`/data`, sdb1 — ditemukan saat audit G5; postgres `/data/postgres`, minio `/data/minio`).

## Kondisi sebelum

- Belum ada unit systemd PMMI (ops-monitor/backup tidak terpasang).
- `backup_runs` tabel sudah ada (schema code-complete).
- `OPS_TOKEN` terisi di env.
- Host belum punya `pg_dump`/`psql`/`mc`; user service `pmmi` belum ada.

## Implementasi

### Repo (commit 20be6ea, 64b0ea8, 0fe4139)

- `infra/scripts/ops-monitor.sh`: default `DISK_PATH=/` (bukan `/srv/pmmi`); cek 9Router menyertakan `Authorization: Bearer $NINE_ROUTER_API_KEY` (sebelumnya 401 dianggap unreachable → false alarm); perbaikan bug JSON `printf` (escape `\"` di dalam single-quote menghasilkan JSON invalid → event POST 400).
- `infra/scripts/backup.sh`: default `BACKUP_ROOT=/data/pmmi-backups`; perbaikan capture `run_id` — `tail -n1` mengambil command tag `INSERT 0 1` dari psql (psql 18 mencetak UUID lalu tag) → diganti `head -n1`.
- `infra/systemd/*`: `EnvironmentFile=/home/pmmiserver/pmmi/.env`, `ExecStart=/home/pmmiserver/pmmi/current/infra/scripts/...`, `BACKUP_ROOT=/data/pmmi-backups`; unit ops-monitor TIDAK memakai `ProtectHome=true` (script di bawah `/home/pmmiserver` — ProtectHome menyembunyikannya, 203/EXEC).
- `infra/docker/compose.yml`: `NINE_ROUTER_URL` untuk container di-hardcode `http://pmmi-9router:20128` (nama container di network compose); `.env` di sisi host memakai `NINE_ROUTER_URL=http://127.0.0.1:20128` untuk skrip host (EnvironmentFile menang atas Environment= di systemd).

### Server

1. User system `pmmi` (`useradd -r -s /usr/sbin/nologin -d /srv/pmmi`); `/srv/pmmi` dibuat (juga root Hermes workspaces untuk G4); `chown pmmi:pmmi`.
2. Tools host: `postgresql-client` (pg_dump/psql 18.6), `mc` (RELEASE.2025-08-13) → `/usr/local/bin/mc`.
3. `/data/pmmi-backups` dibuat, owner `pmmi` (750). `/home/pmmiserver/pmmi/.env` → group `pmmi`, mode 640; `chmod o+x /home/pmmiserver` (traversal).
4. Unit systemd di-copy ke `/etc/systemd/system/`, `daemon-reload`, timer di-enable:
   - `pmmi-ops-monitor.timer` — tiap 5 menit (`OnBootSec=2m`, `OnUnitActiveSec=5m`)
   - `pmmi-backup.timer` — tiap malam 02:30 UTC

## Verifikasi

### ops-monitor (systemd, sebagai user pmmi)

```
$ systemctl status pmmi-ops-monitor.service
Active: inactive (dead) ...          # oneshot sukses (tanpa failure)
$ journalctl -u pmmi-ops-monitor.service
PMMI ops monitor completed; disk=... # tanpa event palsu setelah fix auth
```

- Event nyata yang tercatat di `ops_events` (dari run sebelum fix): `9router.unreachable|ERROR|ops-monitor` — membuktikan jalur post_event → DB berfungsi. Setelah fix auth, run bersih (9Router 200 dengan key → tidak ada false alarm).
- Disk saat ini jauh di bawah threshold → tidak ada event storage.

### Restore drill (non-production: DB scratch + MinIO throwaway)

Target: DB `pmmi_restore_drill` di postgres yang sama; MinIO throwaway `minio-drill` di `127.0.0.1:9100` (BUKAN produksi).

```
$ CONFIRM_RESTORE=YES DATABASE_URL=...pmmi_restore_drill MINIO_ENDPOINT=http://127.0.0.1:9100 \
    MINIO_ACCESS_KEY=drilluser MINIO_SECRET_KEY=drillpass123 \
    bash infra/scripts/restore.sh /data/pmmi-backups/20260822T003828Z
./postgres.dump: OK                       # checksum SHA256SUMS lolos
```
