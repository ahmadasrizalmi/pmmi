# G2 — Restriksi Eksposur (Exposure Restriction)

Tanggal: 2026-08-22. Server: `pmmiserver` (Tailscale `100.127.181.108`, LAN `192.168.1.5`).

## Kondisi sebelum (audit 2026-08-22)

`ss -tlnp` menunjukkan binding publik (melanggar baseline §14):

```
0.0.0.0:5432  + [::]:5432    # postgres (compose ai-server /opt/ai-server, container_name postgres)
0.0.0.0:6379  + [::]:6379    # redis    (compose ai-server /opt/ai-server, container_name redis)
0.0.0.0:9000  + [::]:9000    # minio    (docker run standalone, /data/minio volume)
0.0.0.0:9001  + [::]:9001    # minio console
0.0.0.0:2283  + [::]:2283    # Immich (workload terpisah — tidak disentuh per aturan keras)
```

Temuan tambahan saat audit:

1. **MinIO memakai kredensial default** `minioadmin`/`minioadmin123` dan console `:9001` terbuka publik — kritis.
2. **9Router tidak terjangkau dari container API**: `api` (network `docker_default`, 172.20.0.3) memakai `host.docker.internal` yang resolve ke `172.17.0.1` (docker0). DNAT 9router (`-d 127.0.0.1 --dport 20128`) tidak match dari bridge → `Connection refused`. `NINE_ROUTER_URL=http://host.docker.internal:20128` di env lama → jalur AI gateway rusak (latent bug).
3. **Worker container mati 10 hari** (`docker-worker-1 Exited (0)`), error koneksi PostgreSQL saat startup; outbox/reward/lifecycle/Hermes job tidak berjalan.
4. Docker `EnableUserlandProxy: true`; DNAT rules Docker: service yang di-publish `127.0.0.1`-only tidak dapat diakses container lain via gateway.

## Implementasi

### 1. Bind PostgreSQL + Redis (compose `/opt/ai-server/docker-compose.yml`)

```yaml
    ports:
      - "127.0.0.1:5432:5432"
      - "100.127.181.108:5432:5432"
    # redis: 127.0.0.1:6379:6379 + 100.127.181.108:6379:6379
```

Backup: `/opt/ai-server/docker-compose.yml.bak-20260822`. Recreate: `docker compose up -d postgres redis`.

### 2. MinIO — recreate dengan bind loopback+Tailscale dan rotasi kredensial

```bash
docker rm -f minio
docker run -d --name minio --restart unless-stopped \
  -p 127.0.0.1:9000:9000 -p 127.0.0.1:9001:9001 \
  -p 100.127.181.108:9000:9000 -p 100.127.181.108:9001:9001 \
  -e MINIO_ROOT_USER=<rotated> -e MINIO_ROOT_PASSWORD=<rotated> \
  -v /data/minio:/data \
  minio/minio:latest server /data --console-address :9001
```

Kredensial lama (default) dirotasi; nilai baru hanya di `/home/pmmiserver/pmmi/.env` (`MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY`) — tidak di commit.

### 5. Firewall ufw

```
cp /etc/default/ufw /etc/default/ufw.bak-20260822
sed -i 's/^DEFAULT_FORWARD_POLICY=.*/DEFAULT_FORWARD_POLICY="ACCEPT"/' /etc/default/ufw  # kompat docker

ufw default allow outgoing
ufw allow 22/tcp    # ssh

ufw allow 443/tcp   # https (G1)
ufw allow in on tailscale0
ufw --force enable
```

### 6. Perbaikan repo server + line endings

- `/home/pmmiserver/pmmi/current` ternyata **bukan git checkout yang valid**: repo `git init` tanpa commit (branch `master`, seluruh file untracked), origin mengarah ke repo lama `pondokmultimediamunzalan/pmmi-digital-campus` dengan token kedaluwarsa.
- File di dalamnya ber-line-ending **CRLF** (hasil salinan dari Windows) → `infra/scripts/health-check.sh` gagal runtime: `set: pipefail: invalid option name` (dash/bash membaca `pipefail\r`).
- Perbaikan: tambah `.gitattributes` (`*.sh text eol=lf`) di repo, push `e36d00f`; di server `current` diganti clone resmi `https://github.com/ahmadasrizalmi/pmmi.git` (public) + `git config core.autocrlf false`. Diff konten (modulo CR) terhadap dump lama: identik — tidak ada perubahan user yang hilang. Backup dump: `/home/pmmiserver/pmmi/current.bak-20260822`.
- `infra/scripts/health-check.sh` kini lolos: `PMMI health checks passed`.
