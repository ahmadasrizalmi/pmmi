Retry/fallback/circuit breaker: logika `providers.ts` (ProviderUnavailable → FAILED + backoff, circuit setelah 3 failure) sudah live; uji failover penuh menyusul saat channel kedua dikonfigurasi.

**Webhook Resend (signed)**: route `POST /v1/integrations/resend/webhook` (verifikasi Svix: `svix-id/svix-timestamp/svix-signature` + HMAC timing-safe) — **LIVE + teruji**: unsigned payload → 401, non-JSON → 415 (via tunnel publik). Handler: `email.delivered` → delivery `DELIVERED` + `delivered_at`; `email.bounced`/`email.failed` → `FAILED` + `last_error` (match by `provider_message_id` = Resend email id).

### Webhook — **SELESAI & TERVERIFIKASI end-to-end (2026-08-22)**

- User membuat webhook di dashboard Resend (URL `https://ai.pondokmultimedia.id/v1/integrations/resend/webhook`, events `email.delivered`/`email.bounced`/`email.failed`) dan mengirim signing secret `whsec_…`; diset di `.env` (`RESEND_WEBHOOK_SECRET`), api di-restart.
- **Uji Svix-signed** (HMAC-SHA256 `{svix-id}.{svix-timestamp}.{body}`):
  - `email.delivered` → `{"ok":true,"updated":1}` → row delivery `EMAIL|DELIVERED|t` (delivered_at terisi) — **teramati langsung**.
  - `email.bounced` → `{"ok":true,"updated":1}` → row berubah `FAILED`.
- **Event nyata Resend** kini lolos verifikasi (log api `statusCode:200`) dan diproses: row `e9bed5da… | FAILED | email.bounced` (email yang benar-benar bounce) — status delivery ter-update otomatis oleh webhook.
- Catatan: signature invalid/unsigned → 401; non-JSON → 415 (guard bekerja).
- API key Resend user tetap **send-only** — pembuatan webhook dilakukan via dashboard user (secret dikirim manual).

## Temuan konfigurasi: NOTIFICATION_TRANSPORT=mock

Env produksi memakai `NOTIFICATION_TRANSPORT=mock` → `sendExternal()` mengembalikan `mock-<channel>-<uuid>` → delivery tercatat `SENT` **tanpa pengiriman nyata** (lih. `apps/worker/src/providers.ts`). Ini sesuai DEPLOYMENT.md ("Set live hanya setelah provider production siap") — **intentional sementara**, tapi perlu dicatat: delivery `EMAIL|SENT` saat ini TIDAK berarti email terkirim.

Saat satu channel live dikonfigurasi (G3 unlock):
1. isi kredensial channel di `.env` (+ webhook secrets);
2. `NOTIFICATION_TRANSPORT=live`;
3. restart worker; verifikasi `notification_deliveries` mencatat `SENT` dengan `provider_message_id` nyata (Resend id / Telegram message_id / Baileys id);
4. uji retry/fallback/circuit breaker (matikan provider → FAILED → retry backoff → fallback route → SKIPPED 'another route succeeded').
