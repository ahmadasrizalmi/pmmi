## EMAIL (Resend) — LIVE, verifikasi 2026-08-22

Env: `RESEND_API_KEY` (send-only, domain `pondokmultimedia.id` terhubung oleh user), `RESEND_WEBHOOK_SECRET` (placeholder hex — ganti dengan `whsec_...` dari dashboard Resend saat webhook endpoint dibuat), `NOTIFICATION_TRANSPORT=live` (sebelumnya mock).

1. **Direct API send ke inbox nyata (asrizalmi1@gmail.com)** → Resend `200` + message id `ab61ad4f-e113-4842-b3af-50863c4324dc` — email terkirim ke inbox user (bukti delivery nyata).
2. **Jalur worker (outbox → delivery)**: POST `v1/ops/events` (x-ops-token) → notifikasi ops → worker → `notification_deliveries`:
```
EMAIL|SENT|5cd1e22b-4b87-400c-a…   ← provider_message_id Resend NYATA (bukan mock-…)
IN_APP|SENT|-|-
TELEGRAM|SKIPPED|-|channel not linked
```

Retry/fallback/circuit breaker: logika `providers.ts` (ProviderUnavailable → FAILED + backoff, circuit setelah 3 failure) sudah live; uji failover penuh menyusul saat channel kedua dikonfigurasi.

**Webhook Resend (signed)**: route `POST /v1/integrations/resend/webhook` (verifikasi Svix: `svix-id/timestamp/signature` + HMAC timing-safe) siap di API. Endpoint publik baru bisa didaftarkan di dashboard Resend setelah **G1 (tunnel)** memberi URL `https://ai.pondokmultimedia.id/v1/integrations/resend/webhook`; `RESEND_WEBHOOK_SECRET` diganti nilai `whsec_...` dari dashboard.

## Temuan konfigurasi: NOTIFICATION_TRANSPORT=mock

Env produksi memakai `NOTIFICATION_TRANSPORT=mock` → `sendExternal()` mengembalikan `mock-<channel>-<uuid>` → delivery tercatat `SENT` **tanpa pengiriman nyata** (lih. `apps/worker/src/providers.ts`). Ini sesuai DEPLOYMENT.md ("Set live hanya setelah provider production siap") — **intentional sementara**, tapi perlu dicatat: delivery `EMAIL|SENT` saat ini TIDAK berarti email terkirim.

Saat satu channel live dikonfigurasi (G3 unlock):
1. isi kredensial channel di `.env` (+ webhook secrets);
2. `NOTIFICATION_TRANSPORT=live`;
3. restart worker; verifikasi `notification_deliveries` mencatat `SENT` dengan `provider_message_id` nyata (Resend id / Telegram message_id / Baileys id);
4. uji retry/fallback/circuit breaker (matikan provider → FAILED → retry backoff → fallback route → SKIPPED 'another route succeeded').
