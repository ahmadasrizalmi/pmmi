# G6 — 9Router hardening & metering verification

Tanggal: 2026-08-22. Server: `pmmiserver`. 9Router: image `decolua/9router:latest`, container `pmmi-9router` (loopback `127.0.0.1:20128`, data volume `pmmi-9router-data` → `/app/data`).

## Yang diverifikasi

### 1. Routing & auth

```
$ curl -H "Authorization: Bearer <key>" http://127.0.0.1:20128/v1/models
{"object":"list","data":[{"id":"ds/deepseek-v4-pro","object":"model","owned_by":"ds",...}]}

tanpa key → 401
```

DB 9Router (`/app/data/db/data.sqlite`):

```
providerConnections: 1 row  → provider=deepseek, authType=apikey, priority=1, isActive=1
apiKeys:              1 row  → "Default Key", isActive=1   (key = NINE_ROUTER_API_KEY di .env)
providerNodes:        0 rows   ← TIDAK ADA fallback node
proxyPools:           0 rows   ← tidak ada pool
combos:               0 rows   ← tidak ada model combo
```

### 2. Format usage response (`stream:false` vs `stream:true`)

```
POST /v1/chat/completions {"stream":false}
→ JSON bersih (tanpa marker SSE):
  keys: id, object, created, model, choices, usage, system_fingerprint
  usage: {prompt_tokens, completion_tokens, total_tokens, prompt_tokens_details:{...}}
  → format yang diparse PMMI gateway (usage?.total_tokens / prompt/completion) ✓

POST /v1/chat/completions {"stream":true}
→ SSE benar: data: {"object":"chat.completion.chunk",...}
```

Ini mengonfirmasi perbaikan commit `768cf7c` (api mengirim `stream:false` eksplisit): respons non-stream tidak mengandung marker SSE.

### 3. Usage tracking 9Router

`usageHistory` (11 baris) & `usageDaily` (2 baris) terisi — request live (termasuk test agent G4) tercatat per provider/model/token. 9Router mencatat usage sendiri; PMMI gateway tetap accounting source of truth.

### 4. Exposure

`127.0.0.1:20128` loopback-only (dari G2); admin/API 9Router tidak publik.

## Temuan & gap

1. **Fallback BELUM dikonfigurasi** (`providerNodes`/`proxyPools`/`combos` = 0). Bila deepseek gagal, tidak ada provider cadangan. Dibutuhkan key provider kedua (dependensi user) untuk mengonfigurasi fallback di 9Router, lalu verifikasi failover.
2. **Metering ledger produksi (reservation → settle/reconcile/refund + stream:false) belum diverifikasi live**: membutuhkan user terautentikasi dengan AI wallet + kredit. Saat ini `ai_api_keys` = 0 baris, dan tidak ada kredensial login yang tersedia (bootstrap token sudah dihapus sesuai G2). Bukti tidak langsung: `ai_usage_logs` 6 entri (Aug 12), wallet santri 84 / asrizalmi 50 — jalur pernah berfungsi. Verifikasi end-to-end dituntaskan di G7 (E2E) setelah G1–G3.
   - Logika metering (reserve/reconcile/refund, `stream:false` handling, immutable ledger) sudah dicover test CI (`blueprint.test.ts`) — repository-complete per kontrak.

## Status

**G6 SEBAGIAN**: routing + format usage + tracking + exposure = verified. Fallback = gap (butuh provider key kedua, user). Metering ledger live = menunggu G7/auth.

## Saran hardening

- Konfigurasi fallback provider di 9Router setelah key kedua tersedia (mis. provider kedua dengan priority lebih rendah), lalu uji failover dengan mematikan provider utama sementara.
- Rotasi `NINE_ROUTER_API_KEY`/JWT secret 9Router bila perlu; `jwt-secret` & `machine-id` di volume hanya readable root.
